# Manual QA roadmap — ручна перевірка нових систем

Автотести (`npm run visual`, `check:layouts`) ловлять **overflow + зони + CTA-в-actions**.
Цей чек-лист — про те, **чого вони НЕ бачать**: вигляд, анімація, інтерактив, спрацювання CTA.

> Правило: не дублюй автотест очима. Перевіряй СМИСЛ (тап рахується? CTA стріляє? гарно?).

---

## 0. Як відкрити (два шляхи)

### A. На телефоні через gh-pages (найчесніше — реальний девайс)
```bash
# зібрати всі шаблони в окремі HTML + index, запушити на gh-pages
# (скрипт-збірку зробить асистент; результат — https://serhiidubei.github.io/playableads/)
```
Відкриваєш URL з телефона → тапаєш картку → тестуєш. Реальний thumb-reach, реальний рендер шрифтів/анімацій.

### B. Локально в браузері (швидко ітерувати)
```bash
npm run menu cyber-heist <layout>     # збирає у test/menu-playable/index.html
npx serve test/menu-playable          # або будь-який статик-сервер
# відкрити http://localhost:3000  + DevTools device toolbar (iPhone SE / Pixel 7)
```

### Debug-оверлей (працює скрізь)
- `…/index.html?zones=1` — бірюзові рамки зон + підписи. Перевір, що елементи в своїх смугах.

## Фаза 1 — Зонова система (ядро) · P0 · ~20 хв

Збери **showcase** (`npm run menu cyber-heist showcase`) — він прокручує всі архетипи на 10 екранах.

| # | Що перевірити | Як | ✓ |
|---|---|---|---|
| 1.1 | CTA дістається великим пальцем (не тягтись) | відкрий на телефоні, тапни головну кнопку однією рукою | ☐ |
| 1.2 | Зони не «їдуть» між екранами | гортай menu→game→…→endcard, дивись чи стабільні позиції | ☐ |
| 1.3 | `?zones=1`: кожен елемент у своїй смузі | додай `?zones=1`, переключай екрани | ☐ |
| 1.4 | Ієрархія кнопок читається | головна (primary) явно більша/яскравіша за решту | ☐ |
| 1.5 | На вузькому (iPhone SE 375) і широкому (tablet) — не криво | поміняй девайс у DevTools / відкрий на різних | ☐ |

## Фаза 2 — Шаблони по одному · P1 · ~5 хв кожен

Для кожного: `npm run menu cyber-heist <id>`, відкрий, пройди сценарій.

| Шаблон | Сценарій (що зробити) | Очікувано | ✓ |
|---|---|---|---|
| `endcard` | глянути екран, тапнути Install | hero по центру, CTA домінує, тап → консоль `onCTAClick` | ☐ |
| `pick-hero` | тапати ◀ ▶ | герой змінює hue, ім'я/рівень/крапки оновлюються, CTA «Play as <name>» | ☐ |
| `tap-reveal` | тапнути героя 5× | лічильник росте 0→5, після 5 авто-перехід на reward | ☐ |
| `progress-reveal` | глянути xp, тапнути Continue | XP-бар наповнюється анімовано, перехід на level-up | ☐ |
| `two-choice` | тапнути Attack або Defend | обидва ведуть на outcome (ілюзія вибору) | ☐ |
| `match-cluster` | тапати плитки | плитки того ж символу зникають, після 2 матчів → reveal | ☐ |
| `feature-grid` | глянути | 2×2 картки рівні, не наїжджають, CTA знизу | ☐ |
| `feature-list` | глянути | 3 рядки читабельні, іконки на місці | ☐ |
| `tutorial` | Next → Next → Install | крапки прогресу оновлюються (●○○→●●○→●●●), слайд-перехід | ☐ |
| `menu5` | клікати всі кнопки | навігація між 5 екранами працює, back повертає | ☐ |
| `showcase` | пройти всі 10 екранів | повний тур без застрягань | ☐ |

**На що дивитись скрізь:** анімації плавні (не смикаються), текст не обрізаний, кнопки реагують на тап (scale/підсвітка), CTA пише в консоль `[FbPlayableAd] onCTAClick`.

```bash

npm run menu cyber-heist-cheap endcard
npm run menu urban-runner endcard
```
| # | Перевірити | ✓ |
|---|---|---|
| 3.1 | Кожен стиль рендериться без битих ассетів | ☐ |
| 3.2 | Зони однакові незалежно від стилю (бо геометрія від BASE, не від картинки) | ☐ |
| 3.3 | Вага файлу < 2 MB (білдер друкує `% of 2MB`) | ☐ |

## Що робити, якщо знайшов баг
1. Признач серйозність: **blocker** (не працює) / **major** (криво) / **minor** (косметика).
2. Запиши: шаблон + стиль + девайс + крок + що очікував/що сталось.
3. Якщо це зона/overflow — додай `?zones=1`-скрін; асистент полагодить і прожене `npm run visual`.

## Пріоритет проходження
Фаза 1 (ядро) → Фаза 2 (шаблони) — це 80% цінності. Фази 3-5 — за наявності часу.
