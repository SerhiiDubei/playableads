# User-flow анкета — 20 питань (Designer Studio)

Мета: зафіксувати, ЯК дизайнер має проходити Studio, щоб закрити поточні діри
(нема генерації з UI, вибору стилю, редагування плану, cost-gate, ітерації, експорту).

**Як відповідати:** просто пиши номер + відповідь (можна коротко / обрати варіант / свій).
Не мусиш усі за раз. З відповідей зберу `USER-FLOW-DECISIONS.md` + UX-беклог.

---

## A. Вхід та Brief
1. **Перший екран Studio** — що дизайнер бачить одразу? _(порожнє поле брифа · каталог готових · останні проєкти · вибір «нова з нуля / з існуючої»)_
2. **Референси** — як додавати? _(перетяг файлів · кнопка завантаження · URL · вставка з буфера)_. Завжди обов'язкові чи можна без?
3. **Промт** — вільний текст, структуровані поля (жанр/ЦА/тон), чи обидва (вільний + авто-розкладка в поля)?
4. **Збереження брифа** — авто на кожну зміну чи по кнопці? Скільки версій тримати + чи показувати історію?

## B. Механіка
5. **Вибір** — система сама бере суперкнопку (1 клік) чи завжди показує топ-3 для вибору? Потрібен «здивуй мене» (рандом)?
6. **Створення нової механіки** — це дія дизайнера чи лише девелопера? Хто пише код гри (`game.ts`)?
7. **Комбінація 2 механік** — у v1 чи відкласти? Якщо так — як у UI (перетягнути 2 картки разом)?
8. **Картка механіки** — що на ній? _(назва+опис · прев'ю-гіфка · CTR/метрика · «грати приклад»)_

## C. Стиль
9. **Коли обирати стиль** — до механіки, після, чи паралельно?
10. **Стиль** — пресети (3-5) + власний? Власний задається лише референсами чи й текстом?
11. **Перемкнути стиль** на готовому playable одним кліком (той самий геймплей, інший скін) — треба в v1?

## D. План, генерація, вартість
12. **План екранів** — дизайнер бачить і редагує перед генерацією, чи це «під капотом» (авто)?
13. **Cost-preview** — показувати завжди перед ген, чи лише коли вартість > порогу?
14. **Запуск генерації** — один клік «зробити все», чи покроково (assets → перегляд → build)?
15. **Під час генерації** — що бачить дизайнер? _(прогрес по стадіях · можна перебити · проміжні ассети наживо)_

## E. Прев'ю та ітерація
16. **Прев'ю** — один екран чи всі (свайп/таби)? Девайс за замовчуванням (iPhone/Pixel/власний)?
17. **Не подобається — що робить дизайнер?** _(перегенерувати 1 ассет · змінити промт · правити вручну · відкотити версію)_
18. **Версії playable** — як показувати? _(історія збоку · порівняння A/B · «зробити поточною»)_

## F. Вихід, онбординг, помилки
19. **Готовий playable** — як віддати? _(завантажити HTML · посилання-прев'ю · прямий експорт у Meta · QR на телефон)_
20. **Коли ламається** (валідація fail / ген впав / >2MB) — як показати по-людськи + що запропонувати далі?

---
**Бонус (не обов'язково):** хто користувач Studio — внутрішній дизайнер, зовнішній клієнт, чи обидва? Це змінює defaults (більше defaults для клієнта, більше контролю для дизайнера).
