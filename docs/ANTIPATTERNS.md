**Читай перед роботою.** Половина «нових» багів — уже зустрінуті й тут пояснені.
Кожен запис: ЩО пішло не так → ПРИЧИНА → ПРАВИЛО/КОНТРАКТ, що з цього народився.

Два розділи: **A. Процесні антипатерни** (через них усе й повторюється — найважливіше)
і **B. Технічні регресії** (історичний реєстр).

## A. Процесні антипатерни (META — саме вони ведуть до повторення)

### A1 — Фріланс замість напрацьованого (сесія 2026-06-26) 🔴
**Що:** Для `labs/avoid-the-accident` зробив UI з нуля — HUD намалював примітивами
Pixi `Graphics`, ендкард спершу теж Pixi, потім створив **паралельний** модуль
`src/assetgen/kit/ui.ts` (`buildEndcard`) + окремий user-global скіл `playable-menus`.
При цьому **не використав** наявне: `kit.ts` (SSOT компонентів), `layout.ts` (зони),
`layouts/endcard.ts`, lint R1–R6, і задокументований `docs/playable-menu-skill.md`.
**Причина:** не зробив ревізію наявного перед побудовою; почав як greenfield.
Структурна першопричина — **нема root `CLAUDE.md`**, тож `repo/CLAUDE.md` з усіма
правилами не вантажився при роботі з кореня.
**Правило:** root `CLAUDE.md` §3.1–3.2 — **ревізія перед створенням; UI = kit, не
Pixi-малювання, не паралельний модуль**. Один SSOT.

### A2 — Перевідкриття вже задокументованої проблеми (сесія 2026-06-26) 🔴
**Що:** Вгробив ~15 ітерацій на «порожній перший кадр» у headless QA, дебажачи код.
**Причина:** Це **давно відомий артефакт** (див. B14 нижче — headless SwiftShader
cold-GL), записаний у репо ще до мене. Я не читав реєстр проблем → перевідкривав болем.
**Правило:** root `CLAUDE.md` §6 — перед довгим дебагом «дивної» поведінки звірся з
цим файлом.

### A3 — Пропуск пайплайну й гейтів (сесія 2026-06-26) ⚠️
**Що:** Збудував лаб без дизайн-контракту, **жодного разу** не запустив
`check:layouts`, не вів `BUILD-LOG`, не оновлював `backlog`.
**Причина:** пайплайн не enforced і не був у контексті (див. A1 першопричину).
**Правило:** root `CLAUDE.md` §4 (зафіксований пайплайн) + §3.4 (гейт перед "готово").

### A4 — Дублювання governance (сесія 2026-06-26) ⚠️
**Що:** Створив user-global скіл `playable-menus` + memory, що дублюють наявний
`docs/playable-menu-skill.md`.
**Причина:** не перевірив наявні скіли/доки перед створенням.
**Правило:** §3.1 ревізія-перед-створенням поширюється і на скіли/доки/memory.

> **Спільна першопричина A1–A4:** правила існували, але не в контексті + нема
> enforced-гейтів. Фікс: root `CLAUDE.md` (вантажиться з кореня) + цей реєстр +
> §5 єдиний чекліст. Борг, що лишився прибрати: звести `ui.ts` ↔ `kit.ts`,
> примирити скіл ↔ `menu-skill.md`, перевести `avoid-the-accident` UI на kit.

## B. Технічні регресії (історичний реєстр)

### B1 — 5057 button regression 🔴
**Що:** текст на кнопці виглядав скошеним. **Причина:** showcase тримав власну копію
CSS компонента, розійшовся з kit; виправлений баг центрування «воскрес» на копії.
**Правило (Kit #1):** `kit.ts` = SINGLE SOURCE OF TRUTH; білдери лише консумують
`loadKit()`+`makeKit()`, ніколи не дублюють CSS/рендер. *Два джерела ВЖЕ розійдуться.*

### B2 — Asymmetric frame centering
**Що:** текст лежав криво навіть у геометричному центрі. **Причина:** `btn-frame`
асиметричний (панель зміщена -12% вгору); `text-align:center` лягає у геом-центр, не
у видимий. **Правило (Kit #2):** frame/template-ассети симетричні (верт.+гориз.);
перевіряй `sharp` panel-analysis (bright-region vs geometric center), **не оком**.

### B3 — Viewer-trust артефакт
**Що:** чистий cutout виглядав із сірим/червоним фоном у переглядачі. **Причина:**
viewer композитить прозорість на non-neutral тлі. **Правило (Kit #3):** alpha/geometry
вимірюй інструментально (`sharp`), **ніколи не довіряй переглядачу**.

### B4 — 1 MB inline blowup
**Що:** файл роздувся до 1 MB. **Причина:** великий bg `url(dataURI)` повторений у
CSS 5× (per-screen). **Правило (Kit #4):** великий асет inline **рівно один раз**
(CSS-клас / `:root` var), ніколи per-element. (Фікс → 477 KB.)

### B5 — Responsive layout bleed
**Що:** елементи «пливуть» на вузьких/широких екранах. **Причина:** спроба fluid
`vw/vh/flex`. **Правило (Kit #7):** responsive = фіксований design-canvas (400×860)
`#stage` + `scale` (`stage.ts`), НЕ fluid CSS; компоненти у fixed px.

### B6 — Feature-grid CTA overflow (R1)
**Що:** CTA виліз 137px за edge. **Причина:** невідома висота контенту, padding не
врахував CTA. **Правило/фікс:** sticky CTA `position:absolute;bottom:20px;left:24px;right:24px`
+ lint R1 (no-overflow).

### B7 — Tutorial panel over-content (R1)
**Що:** Next-кнопка 17px за екран на step 2. **Причина:** завеликий шрифт панелі з'їв
місце під CTA. **Правило:** зонна смуга прив'язана до контенту, не ad-hoc padding.

### B8 — Step-progress misalignment (R1)
**Що:** `.step-progress` 13px вправо за canvas. **Причина:** `left:0;right:0` без
центрування. **Правило:** горизонтальне центрування — `left:50%;transform:translateX(-50%)`.

### B9 — Hero size overflow (R5)
**Що:** hero 230px > 200px ліміту. **Причина:** layout не оголосив обмеження.
**Правило (R5):** layout оголошує `meta.maxHeroPx`, коли простір обмежений.

### B10 — Menu5 false-positive CTA (R3→R6)
**Що:** лінт спіймав робочі кнопки як Install-CTA. **Причина:** R3 шукав CTA per-screen.
**Правило (R6):** одна Install-CTA на playable (layout-level), не на кожному екрані.

### B11 — Dream-floor perspective drift
**Що:** дошки підлоги «підпиляні», не паралельні фону. **Причина:** 1-точкова
перспектива проти 2-точкового фону. **Правило:** AI-арт на цілу сцену — перспектива
це механіка, не опція; вимірюй (structure tensor / VP2), live-калібруй (`?floor`).

### B12 — Carpet alpha (edge-to-edge)
**Що:** килим мав білу рамку. **Причина:** генерація з `alpha:false` → фон на білому.
**Правило:** кожен AI-асет має explicit `transparent:bool` в override; default = true.

### B13 — Pulse-ratchet endless growth (state-bug)
**Що:** idle-нудж щоразу `pulse()`-ив об'єкт → безмежне зростання. **Причина:**
повторний pulse живого (масштабленого) tween перемальовував базу масштабу.
**Правило:** у Pixi state-машині перед анімаційним викликом перевір, чи tween уже біжить.

### B14 — Headless cold-GL чорний/порожній кадр (infra) 🔴 *(див. A2)*
**Що:** headless SwiftShader інтермітентно не комітить перший композит (порожній/чорний
кадр); патерн «перший прогін рендерить, наступні порожні». **Причина:** холодний GL-
контекст + shader/MSAA-resolve у headless; це **артефакт середовища, не код** (теплий
контекст рендерить 100%; реальний GPU не має). **Правило:** не дебаж код під це;
`antialias` лише під `?dbg`; для надійних скрінів — теплий throwaway-контекст або
`renderer.extract()`; харнес завжди закриває браузер у `finally`.
