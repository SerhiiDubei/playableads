# Session log — 2026-06-01 · Layered UI architecture + playable games

Build a **layered system** on top of the existing kit so that screens (and whole playable games)
are assembled from validated data, then stress-test it by building two real interactive playables.

## TL;DR

Added 4 architecture layers (catalog → groups → zones → flow) + a `scene` (background-mood) layer,
and assembled **two playable games** entirely from them. Everything passes `visual-test` (8 viewports),
stays under the 2 MB budget, and typechecks clean. A research-backed game-design pass produced 5 fixes.
Identified the next big gap: a **Design Critic** layer (we validate *structure*, not yet *quality*).

## What was built

### Architecture layers (new)

| Layer | File | Answers | Notes |
|---|---|---|---|
| **Zones** | `kit/layout.ts` | *Where* on screen | +archetypes: immersive/focal/split/grid/dense/battle/puzzle; **inner-element overlay** (`?zones=1`) shows component layers, not just zone bounds |
| **Catalog** ("bible") | `kit/catalog.ts` | *What* each component is + how to generate it | `ComponentSpec` (family, layer/z-order, slots, `gen` recipe). 11 components |
| **Groups** | `kit/groups.ts` | *Who* + *by which rules* (families) | 13 groups, 5 rules each (zones/max/level/intent/readonly); `composeScreen` + `validateRecipe` |
| **Flow** | `kit/flow.ts` | *Function* + *how screens connect* | `ScreenSpec` (purpose/scene/mechanic/transitions) + `validateFlow` (reachability, CTA path, `mechanic ⇒ scene:focus`) |
| **Scene** | (in builders) | *Atmosphere/beat* | `world`/`focus`/`celebration` → CSS treatment of **one** bg (no extra weight) |

Generated docs: **`docs/KIT.md`** (`npm run catalog`) — human/agent-readable bible of components + groups.

### Validation philosophy

- `validateRecipe`: **1 focal action** per screen = a primary button **or** a play-group (games).
- `validateFlow`: graph integrity + "a mechanic screen must use `scene:focus`" (so gameplay bg never competes).
- `visual-test` now **auto-discovers screens** from the DOM → works on any build.

### Game-design pass (research-backed)

Read: [Microsoft — playable best practices](https://about.ads.microsoft.com/en/blog/post/november-2024/best-practices-for-playable-ads) (eye-tracking AOIs),
[GameAnalytics — FTUE](https://www.gameanalytics.com/blog/tips-for-a-great-first-time-user-experience-ftue-in-f2p-games),
[Game Feel / juice (Swink)](https://en.wikipedia.org/wiki/Game_feel). Applied 5 fixes to `connect`:

1. **Open on gameplay** (entry = puzzle, not menu) — hook in the first 3 s.
2. **Tutorial hand** — animated gesture demos the first drag, hides on first grab.
3. **Juice** — snap spring + socket pulse on match; shake + red flash on wrong drop.
4. **Reward** — stars + "Reward: 500 Gold" toast on win.
5. **Single focus** — gems are the focal action (validated as play-group).

## Weak spots / what's still raw (honest)

- **No Design Critic layer.** We validate *structure* ("assembled correctly?") but nothing judges
  *quality* ("is it actually good / engaging?"). **This is the biggest gap** and the next priority.
- **Gameplay background is a half-measure** — we dim the menu bg instead of a purpose-built backdrop
  designed to recede.
- **Levels differ only by count/order** — no escalation of *feel*; needs a real twist per level.
- **No audio** — half of "juice" is dead (autoplay policy; enable on first tap).
- **Win reward underwhelming** — small stars; the climax should hit harder.
- **Mixed art styles** in `experiments` (pixel-art hero in painterly frames) — readability ok, cohesion off.
- **First focus on the puzzle is split** between sockets (top) and gems (bottom).

## Next steps

1. **Design Critic layer** = static design-lint (open-on-game, ≤1 mechanic, AOI count ≤3–4, reward present,
   single focal, hint present) + a critique rubric (vision pass over screenshots, 1–5 per dimension) +
   an explicit `focus` field per screen ("what the eye must catch first").
2. Dedicated **gameplay background**; stronger **reward**; **level escalation**; **sound** on first tap.
3. Promote **hand-hint** and **juice** into reusable kit components so every new game gets them free.
