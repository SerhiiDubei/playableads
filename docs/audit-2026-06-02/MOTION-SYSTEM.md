# Система контролю руху (grounded у реальному Fruit Ninja Retro / Unity)

Джерело: декомпільований `Assembly-CSharp.dll` (Mono) з itch-білда Fruit Ninja Retro.
Це переводить нашу систему руху з теорії в **числа з реальної гри**.

## Чому наші ігри «літали» (root cause, підтверджено кодом)

| Наша помилка | Реальна гра |
|---|---|
| Фрукти летіли **впоперек** екрана, швидко | Летять майже **прямо вгору** (`Vector2.up`, відхил `maxShootingAngle=10°`) |
| `x += speed` (стала швидкість, нема зависання) | **Фізика + гравітація** → парабола, **зависання на піку** = вікно розрізу |
| Розгін **швидкості** за часом (`elapsed*0.012`) | Швидкість стала; росте **щільність**: `parallel 1→5`, `wait 2s→0.3s` |
| Складність за таймером | **Адаптивна**: difficulty = % влучань за 20 останніх; бомба −20% |
| px/кадр (залежить від fps/екрана) | world-units (поле = **9 юнітів заввишки**), фізика в FixedUpdate (dt-correct) |

## Реальні числа (Spawner / DifficultyAdapter / AspectRatio)
- Поле: **9 units tall**, spawn-band width 10.
- Кидок: `AddForce(Vector2.up * power)`, кут ±10°, + `AddTorque` (обертання).
- Каденс спавну `_wait`: lerp **waitMin=0.3s ↔ waitMax=2s** (±50% дев).
- Паралельних об'єктів: **1 → 5** (за difficulty).
- Бомби: ймовірність **0.1 → 0.4**, лише після 5 фруктів.
- Difficulty: ковзне вікно 20 фруктів, = успішні/20; бомба −20%.

## Модель руху для нашого стека (Pixi, без Unity-фізики)
1. **Арка замість лінії:** хелпер `launchArc({ fromX, timeAloftSec, apexFraction })` рахує параболу в часі через `dt` → природне зависання на піку, frame-independent.
2. **Час, не швидкість:** проєктуємо `timeAloft` (≈1.5-2.5с), не px/кадр. Швидкість виводиться.
3. **Частки екрана:** усі величини в `sh` (screen-heights), не px. Еталон як у реалі — поле ~висота екрана.
4. **Ескалація = щільність:** збільшуй паралельність/каденс, **тримай швидкість арки сталою**.
5. **Адаптивна складність:** difficulty = rolling success rate (вікно ~15-20), не elapsed.

## Якісні маркери (тепер grounded, не вгадані)
| Маркер | Поріг | Підстава з реалу |
|---|---|---|
| Траєкторія must-hit | вертикальна арка, не горизонт. трансляція | `Vector2.up` ±10° |
| Час польоту (slice-вікно) | **1.5-2.5с** на екрані | парабола 9-unit поля + гравітація |
| Зависання на піку | швидкість біля апексу → ~0 | гравітаційне гальмування |
| Ескалація | щільність↑, швидкість арки = const | difficulty→parallel/wait, не speed |
| Адаптивність | за % влучань, не за часом | DifficultyAdapter |
| dt-незалежність | Δ<5% на 30/60/120fps | фізика у FixedUpdate |

## Артефакти (план)
1. **`src/assetgen/kit/motion.ts`** — `launchArc()`, токени часу-польоту, `DifficultyController` (rolling success → density/cadence). Єдине джерело руху; генератор бере звідси.
2. **`motion-lint`** (Playwright) — інструментує playable, трекає позиції об'єктів у часі → асертить: час-на-екрані ≥1.2с, траєкторія вертикальна, швидкість арки стала при ескалації, dt-незалежність. FAIL = надто швидко.
3. **Схема refgames** — `motion: { timeAloftSec, apexFraction, escalation: "density", adaptive: true }` на механіку. Гра виводить рух із цього.
